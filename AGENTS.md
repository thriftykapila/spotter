# Spotter development

Build a straightforward route planning tool. Keep the system font, restrained surfaces,
one blue action accent, and semantic risk colors. No decorative gradients or marketing hero.

Risk and recommendation decisions belong on the backend. Missing weather is unknown,
never low risk. No Travel routes cannot be recommended. Do not round before scoring.

Run focused tests for each change. Before release run backend tests, frontend tests,
TypeScript/build, browser checks, and `manage.py check --deploy` with production settings.
Keep credentials out of source and logs. Use small coherent commits with brief messages.
